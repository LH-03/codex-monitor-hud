# 底层优化复查：2026-09-12

本轮以 `df1d5b9`（3.2.2）为基线，优化 C# 常驻监控路径；没有修改 XAML、默认配置、配色、显示字段、快捷入口或动画参数。源码修改和可运行构建已落地，未安装到用户当前插件目录，也未发布 GitHub Release。

## 检查范围与处理结果

| 范围 | 处理 |
| --- | --- |
| 增量日志读取 | 向量化换行搜索，完整行直接解码，跨块记录才复制；取消重复 FileStream 缓冲；无换行尾记录直接验证 UTF-8；大记录结束后释放超过 128 KiB 的 pending 容量。 |
| 启动时倒读日志 | 用分段扫描、直接解码与池化跨块拼接替换逐字节追加及反转；保持 32 MiB 搜索上限、8 MiB 单行限制和 8,192 行深度。 |
| 完成事件解析 | 在 JsonDocument 现有 UTF-8 存储上判断正文是否为空白，支持中文、Unicode 空白与 JSON 转义，不再生成整段回复字符串。 |
| 历史目录发现 | 使用目录枚举已有的 FileInfo 元数据，避免为每个历史文件重新查询磁盘；保留旧日期会话恢复、锁探测及全局候选上限。 |
| 文件变化队列 | 有界 HashSet 加短锁替代 ConcurrentDictionary 的全表 Count/Keys 操作；原子取走路径；处理 dirty 标记消费与路径取走之间到达的事件。 |
| 聚合与额度合并 | 一轮遍历累加计数，额度单独线性选择两种窗口的最新观测；保持时间并列时的先到优先、未知成本、整数溢出语义。 |
| 指标格式化 | 只格式化实际显示的字段；汇总栏无需先生成随后丢弃的任务指标。上下文告警计数省去无意义排序。 |
| 刷新调度 | 单次 tick 复用可见任务集合；整体状态计算减少中间数组与排序，刷新频率不变。 |
| WPF 外观与画刷 | 外观未变时跳过包含整个主题的字符串签名；画刷缓存改用值类型键，缓存命中无需拼接字符串。 |
| 价格匹配 | 保留原有五层别名上限，去掉每次直接价格查询也要分配的 HashSet。 |
| 官方额度进程 | stderr 直接排空到 Stream.Null；一个取消定时器覆盖读取期限，取消逐行创建延迟任务。官方额度来源、刷新周期及退出清理不变。 |
| Settings、主题、安装、MCP | 检查与常驻程序的边界及原有回归；按需 Settings、安装回滚和 MCP 协议未重写。 |

复用 .NET 自带的 Span、ArrayPool、UTF-8 JSON 能力，没有引入第三方运行依赖。参考过 [.NET 官方 UTF-8 读取示例](https://github.com/dotnet/docs/blob/main/docs/standard/serialization/system-text-json/use-utf8jsonreader.md)；实现按现有 HUD 的返回值、预算和兼容行为调整。

## 测量方法

同机 Windows 10.0.26200、.NET 10.0.10、Release 构建。旧版由本地 Git `df1d5b9` 导出，使用与新版相同的新增测试程序。性能对比设置 `DOTNET_TieredCompilation=0`，避免两边落在不同 JIT 分层阶段；这仅是测试环境设置，没有修改产品运行设置。

只使用合成数据。核心测试先预热 5 次，再执行表中的迭代次数；文件处于暖缓存。分配量是当前线程累计托管分配除以操作次数，**不是常驻内存或进程工作集**。耗时是本次机器负载下的微基准结果；尤其亚微秒项目只能说明开销方向。

| 工作负载 | 次数 | 旧版每次 | 新版每次 | 旧版分配 B/次 | 新版分配 B/次 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 64 个任务聚合 | 10,000 | 8.52 μs | 2.99 μs | 4,856 | 1,496 |
| 64 个任务额度合并 | 10,000 | 2.12 μs | 0.40 μs | 3,008 | 296 |
| 增量读取 5,000 行 | 20 | 1.274 ms | 0.742 ms | 2,277,492 | 2,212,276 |
| 倒读含 4 MiB 大记录的日志 | 15 | 12.805 ms | 4.811 ms | 25,249,018 | 8,406,752 |
| 解析 512 KiB 完成正文 | 100 | 360.30 μs | 75.46 μs | 1,049,138 | 384 |
| 扫描 2,000 个历史文件 | 5 | 188.717 ms | 47.526 ms | 902,438 | 1,031,542 |
| 直接模型价格查询 | 10,000 | 0.062 μs | 0.023 μs | 216 | 40 |
| 少量可见字段的汇总格式化 | 10,000 | 2.00 μs | 0.31 μs | 1,864 | 224 |

目录扫描是明确的取舍：多分配约 126 KiB 的文件元数据对象，换取这次测试约 141 ms 的耗时下降。没有把这项写成“内存也减少”。

WPF 测试直接调用实际 MainHudView / TaskBubbleView，使用 6 个合成任务，禁用更新动画和静默折叠，预热 30 次，测量 500 次内容不变的刷新及布局。反射调用的固定开销包含在两边。普通及深色配色结果一致：

| 表面 | 旧版分配 B/次刷新 | 新版分配 B/次刷新 | 减少 |
| --- | ---: | ---: | ---: |
| 汇总 | 14,932 | 10,188 | 31.8% |
| 列表 | 31,177 | 19,376 | 37.9% |
| 单个气泡 | 3,688 | 248 | 93.3% |

这些是一次实际刷新调用的分配量。产品本身会跳过没有变化的完整刷新，因此不能按刷新频率直接换算整机 CPU 或常驻内存收益。没有声称整款 HUD 提速相同倍数。

## 已完成验证

- 基线与新版都通过 19 组 Core 回归；新增样例覆盖随机跨块长行、中文及 emoji、CRLF、空行、BOM、无换行尾记录、截断、超过上限的记录恢复、完成正文空白、时间并列与计数溢出。
- 新版通过 `scripts/test.ps1`：PowerShell/XAML、会计口径、主题、本地化、MCP、编号、安装协议和回滚等原有检查。
- Release 编译零警告、零错误；`runtime/win-x64/app` 的构建通过 staged health check。
- 旧版与新版各渲染汇总、列表、气泡的普通/深色配色，共六对 PNG；逐像素比较全部 **0 个差异像素**。使用真实 WPF 控件离屏渲染，未启动常驻 HUD。

GUI 隔离运行测试请求被拒绝，未执行。实际桌面上的拖拽、混合 DPI、多显示器、鼠标穿透、分离窗口、动画和长时间运行的 CPU/私有内存/工作集变化，本轮没有新的实测证据。六对静态图不代表这些场景已验收。

## 继续优化的边界

官方额度仍定期创建 app-server 子进程，Windows 活跃任务源仍定期打开 SQLite。它们可能比微小 UI 对象更影响整机资源，但改成长连接会增加常驻内存，并引入账户切换、数据库替换和失效恢复问题；本轮只做不改变这两条数据源语义的优化。是否值得改结构，需要获准运行后采集整机进程指标再决定。

另一个独立行为问题：MCP `readTaskRegistry` 的百分比转换使用 `Number(value)`，`null` 会被转换成 0。它属于额度未知值语义修复，不是保持现有输出的性能优化，本轮没有混入修改。

本轮没有重写非热点 Settings，也没有通过削减监控范围、降低刷新频率、关掉动画或改变未知模型支持来换数字。

## 复现与本地证据

核心测试入口：`scripts/test-dotnet.ps1`。核心基准：

```powershell
$env:DOTNET_TieredCompilation = '0'
dotnet run --project tests-dotnet/CodexMonitorHud.Core.Tests -c Release -- . --benchmark
dotnet run --project tests-dotnet/CodexMonitorHud.Render.Tests -c Release -- . .test-output-render
```

没有全局 SDK 时使用仓库 `private/toolchain/dotnet/dotnet.exe`。渲染测试是 Windows 专用的显式入口，使用合成配置，不读用户会话；没有加入平台无关 Core 测试的默认构建链。

本地证据保存在 `.test-output-optimization-baseline/`、`.test-output-optimization-new/` 和 `.test-output-optimization-static-final/`；这些目录被 Git 忽略。关键文件为 `core-benchmark-final.txt`、`core-benchmark.txt`、`core-comparison.json`、`render-benchmark-final.txt`、`render-benchmark.txt`、`pixel-comparison.json`、`health-check.json` 及两组 `render/*.png`。
